## Decision

Use the first observation regardless of its latency. Evaluate main-thread execution and runnable wait against adapter wall. A component taking over half the interval is dominant for **this observation**. Report GC interval intersections and unaccounted time separately. High process CPU alone cannot identify work on the main thread. The constructor's earlier read is a within-case reference for identical input, under different heap/scheduling conditions.

Advance a fix only for a reproduced home adapter breach that exceeds in-window probe cost and boundary uncertainty, with correct work/output and localized, demonstrably avoidable implementation work sufficient to explain the excess. Distinguish source-inferred loop counts from measured phase costs. Re-reading authoritative state is part of the existing contract. Any proposed saving must preserve fresh reads, validation, date/error behavior, independent metadata and write/invalidation safety. A large GC or wait interval without a specific removable cause, a fast observation, a fidelity issue, or an ambiguous comparison leaves attribution **INCONCLUSIVE**. A subsequent default pass would verify only that gate run. Neither observational latency nor a single before/after pair establishes a speedup.
