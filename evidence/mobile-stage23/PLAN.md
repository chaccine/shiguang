### 2. Story representation and editor rules

- **Persist one block sequence.** Paragraph, small heading and quote contain literal text runs with independent bold and italic flags. The other variants are divider and photo containing the existing `PhotoUse`. `coverPhotoUseId` identifies an occurrence. Block position determines order everywhere. Text-block focus keys can stay session-local. Rust validates draft edits against the expected draft state. Typed TS adapters decode untrusted input at IPC and preview-storage boundaries. Reading uses text nodes and semantic elements.
- **Map legacy content losslessly.** A nonempty legacy body becomes one unformatted paragraph, preserving whitespace and embedded newlines exactly. An empty string contributes no paragraph. Append the existing photo uses in array order with their IDs, captions and integrity fields. Preserve every explicit cover, including a non-first cover. Legacy quick/CLI body edits remain supported on simple content. A scalar write against complex content must fail safely. A v5 side field would be discarded on reserialization, and markup inside `body` would change the meaning of existing literal text. [model.rs:178](../../core/src/model.rs#L178) · [model.rs:211](../../core/src/model.rs#L211) · [schema.rs:113](../../core/src/schema.rs#L113)
- **Implement R02/R09 from current structure.** Quick editing allows zero or one leading unformatted paragraph followed only by photos, including photo-only content. A second paragraph, text after a photo, heading, quote, divider or emphasis makes it complex. New starts quick. A simple draft resumes its last mode, persisted on the draft. Complex drafts and complex formal Edit open in story. Manually switching those to quick protects **all** fields and actions, including tags, date, cover and commit, with an explicit **进入故事编辑** entry. Simplifying restores quick editing. Opening, previewing or accepting the default date alone creates no draft. ### 3. Migration, rollback and merge

**Write `state.json` with `version=2, schemaVersion=6`.** The second guard is deliberate. The current v5 reader checks `schemaVersion`, but the earliest repository reader defaults absent `body` and `photos` to empty and checks only the outer state `version` (`425e57c:core/src/model.rs:117`, `425e57c:core/src/store.rs:562`). The new reader accepts legacy outer version 1 with absent/explicit schema 1 through schema 5. Keep plain `.sgbak` format 1, encrypted `SGBAKENC` v1 and the application version. New backup manifests declare schema 6. [schema.rs:40](../../core/src/schema.rs#L40) · [backup.rs:448](../../core/src/backup.rs#L448) · [crypto.rs:399](../../core/src/backup/crypto.rs#L399)

**Make migration reversible before admitting writes.** Under the existing write lock, preflight the version, save and verify the exact original bytes in `backups/state.schema-v{from}…json`, then transform every formal, draft, trashed and conflict snapshot in memory. Validate and round-trip the candidate before same-directory temp write, sync and atomic replacement. Media files need no migration. The current migration ignores the durability result of the final replacement. Add a small pending-migration record with old/new hashes and the backup name. Pre-replacement failure leaves the old file intact. On interruption or uncertain post-rename sync, resolve under lock before opening a writer, atomically restoring the verified old bytes for an uncommitted migration. Reject unknown versions before cleanup or writes. [store.rs:435](../../core/src/store.rs#L435) · [store.rs:485](../../core/src/store.rs#L485) · [persist.rs:102](../../core/src/persist.rs#L102)

**Separate occurrence identity from the current asset.** Give each photo use immutable provenance. Derive it deterministically for legacy uses from record origin, original use ID and original asset identity, honoring existing remap entries. New insertions receive a fresh identity. Replacement preserves it. Merge maps each incoming occurrence once across formal, draft and conflict copies, remapping the embedded use and cover together. Compare the complete ordered blocks, marks, captions and cover. Keep existing record revision, tombstone, metadata and media-hash conflict policies. Reimport and re-export must preserve identities without multiplying conflicts. Apply the same rules in the synthetic adapter.
